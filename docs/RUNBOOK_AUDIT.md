## Highest-impact corrections

- **Settlement is not success.** The CLI’s await FSM specially handles question prompts but can settle approval/error prompts as finished. `allFinished` includes failed members. Async settlement uses the same state logic. Procedures now require per-terminal task evidence and recognize that foreground waits retire settled spawn supervisors.
- **A partial launch is not a reason to duplicate work.** The issue-start wrapper can attach a watcher and ledger row without returning their ids. Procedures reconcile those stores and adopt an existing terminal when needed. Missing ids, failed assignment, failed context injection and failed launch are distinct outcomes.
- **Branch preparation needs staged-index discipline.** The readiness workflow is read-only, and git commit consumes the existing index. Procedures scope staging, protect unrelated staged work, push already-existing local commits where requested and find an existing PR before creating one.
- **Relocation has several postconditions.** A panel move does not change a process directory or copy working-tree changes; it can also move an entire tab group. Procedures keep one destination per call and independently verify grouping, agent acknowledgement and supervision scope.
- **Timers teach the shipped contract.** Only `enqueue` and `call_safe_tool` are accepted by the pinned CLI. A timer does not itself wake an assistant conversation. Deferred spawns use a fixed tool payload with a timer-scoped grant; workflow graphs remain records to resume, not scheduled executors.
- **Scope and evidence survive handoffs.** Project-root filesystem reads do not follow the selected worktree, missing snapshot sections mean unknown, and terminal reads have a bounded tail. Runbooks retain actual ids, source attribution, vote maps, partial results and existing authorization.

## Remaining runtime limitations

These findings need implementation work in the owning component; runbook wording provides the recovery path but cannot repair the underlying behavior:

1. **CLI settlement:** approval/error waiting reasons need first-class blocked/stopped outcomes in the shared FSM. Async and foreground waiters should consistently carry evidence limitations. The current runbooks require a tail check to compensate.
2. **Issue-start wrapper:** return the watcher/ledger handles that it creates, plus attachment warnings, so callers do not need a second store lookup. Add task-specific acceptance criteria without silently sending unsupported arguments to Daintree.
3. **Verification freshness:** PR/check roll-ups do not establish that their evidence corresponds to the latest head SHA. Merge-sensitive verification needs a source-bound result; a timed re-read alone cannot close the race.
4. **Dynamic host contracts:** the CLI inventory can validate a wrapper’s outer arguments but cannot validate every forwarded MCP action’s nested schema. Keep live discovery/version checks and action-level tests at that boundary.
5. **Relocation semantics:** moving UI panels does not move the running process, copy edits or refresh an existing watcher’s verification scope. A single atomic relocation capability would need to define those responsibilities explicitly.
6. **Durable execution:** timer records and workflow graphs do not provide general future assistant-turn execution. Fixed timer calls are claimed before dispatch and can fail without retry; do not promise eventual success or automatic graph continuation.
7. **Routing quality:** the unchanged 14 recall misses include branch review, watcher cancellation/cleanup distinctions, worktree/recipe boundaries, PR search versus follow-up, one fleet wake, and multi-intent issue/poll cases. Improving them belongs to selector examples/training and should be measured separately from procedure edits.

No live execution-quality score is claimed. The next integration validation should use a connected disposable project to exercise partial launch recovery, scoped staging, panel relocation, one-shot timer grants and blocked agent prompts.
