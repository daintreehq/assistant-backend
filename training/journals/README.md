# Raw generation journals

Exactly what a generating agent returned, unedited. **Append-only, and
committed.** Nothing trains from these directly; they exist so that a row in the
curated corpus can be traced back to the run that produced it.

```
training/journals/   ← you are here. RAW.
training/corpus/     ← CURATED, edited by hand, the source of truth
training/data/       ← COMPILED, generated by training.compile_corpus
```

## Why they are in the repo

They used to be gitignored, on the reasoning that they were session-local and
`selection.jsonl` was the record. That made the generated artifact the only
surviving evidence, and the generator is a nondeterministic paid model — so a
row could never be traced to a prompt, a bad run could not be identified after
the fact, and the corpus could only be regenerated by feeding its own output
back in.

They are small (a few hundred KB), they compress, and they are written once.

## Naming

    <run-id>--<original name>.jsonl

The run id is what `--run` stamped on every example the journal contributed, so
`grep` from a curated row's `run:` back to the journal is the whole lookup. Make
it identify the generation, not the day it was imported:
`2026-08-29-worktree-runbooks`, not `journal3`.

`pre-split--journal_context.jsonl` is the one journal that survived the old
regime. Every corpus row stamped `run: pre-split` predates the three-plane
split; most of those journals are genuinely gone, and recording that honestly is
better than inventing provenance for them.

## Adding one

```bash
python -m training.ingest_journal <journal.jsonl> --run 2026-08-29-worktree-runbooks
python -m training.compile_corpus
```

`ingest_journal` copies the journal in here, folds its examples into
`training/corpus/`, and skips anything already present — so running it twice
changes nothing. It refuses to overwrite an archived journal whose content
differs, because this is the one plane that cannot be rebuilt from any other:
reuse a `--run` and you get an error rather than a silently replaced record.

Never edit a file in this directory; correct the curated YAML instead, which
is what it is for. Note that ingest's no-op property is about the CORPUS: if
you prune a run and then re-ingest its journal, the rows come back.
