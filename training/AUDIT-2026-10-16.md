# Synthetic selector data audit — 2026-10-16

The curated corpus is ready for a new training run. This audit changes training
data and its checks; it does not retrain, replace or claim an accuracy gain for
the shipped selector weights.

## Scope and evidence

Inventoried all 153 runbook files and all shared sources, checked the complete
22,603-row starting corpus mechanically, and reviewed routing against the current
catalog. Semantic review focused on stale broad labels, new runbook boundaries,
continuations, documentation, compound tasks and obsolete observation mechanisms.
This was not an independent relabeling of every historical row.

Writers used current routing clauses and runbook bodies, without reading
evaluation cases. A different model (`gpt-6-astra`) independently labeled 593
shuffled proposed inputs with authored answers and hard negatives removed. Seven
inputs were marked uncertain; disagreements were either withdrawn, removed as
ambiguous originals, or resolved against the deciding catalog clause. Seventy
state-only documentation variants and 160 history-without-active-state inputs
were independently checked in further batches. Of the latter, 152 retained a
confident empty answer and eight ambiguous originals were omitted.

During the final rebase, PR #156 added 99 examples to `develop`. All 99 were
preserved, independently labeled against its updated routing text (unanimous,
no uncertain labels), and screened against the enlarged evaluation suite. The
audit's own corpus result was 22,396 rows; the combined result is 22,495.

The labeling digest was stale at 105 runbooks; it now contains all 153. Raw
proposals, blind labels, adjudications and exclusion fingerprints are archived
under `training/journals/2026-10-16-synthetic-audit--*`.

## Changes to the data

- Added **401** examples and repaired **160** existing examples. New examples
  include both directions of host boundaries, active-state continuations and
  topic shifts, independent compound tasks, grounded short replies, and product
  questions during real local and host workflows.
- Refined the loaded-state metadata of **106** further existing examples. The
  152 independently checked state controls also include 46 examples already
  added or repaired in this audit. This balances history with and without a
  loaded workflow without changing any latest question or accepted answer.
- Removed **31** ambiguous, incorrectly scoped or impossible examples. Examples
  without a referent are replaced by grounded situations where appropriate.
- Removed **578** original rows with evaluation overlap in their latest question
  or history: 87 exact matches and 504 near matches, with 13 rows in both groups.
  One of those originals has a separately verified repaired input. Near matches
  mean normalized difflib similarity strictly greater than 0.8; they are surface
  overlaps, not proof that a writer copied a case. The exclusion is conservative,
  including short conversational phrases, to honor the corpus's authoring rule.
- Refused 14 proposed inputs that overlapped evaluation text. Evaluation cases
  were never rewritten, paraphrased into training examples or relabeled here.

Repairs move notice cancellation from the generic foundation to `watch-outcome`,
distinguish a current-state read from arranging future observation, replace
histories asserting retired native timers/watchers/grants with real stop notices
or honest limitations, and route live-agent questions and instructions to their
specific owners. Unsupported deferred requests still select `watch-outcome`,
whose procedure explains the actual limits; they are not turned into immediate
actions. Suspected flakes with an already established deterministic failure keep
their existing CI diagnosis label.

The compiled corpus has no dropped rows or silently stripped self-negatives.

## Protections for the next batch

`compile_corpus` now excludes exact collisions with the main benchmark and every
holdout round, including sealed rounds. Previously it protected only the main
benchmark. Queries and all history lines are checked.

`python -m training.audit_leakage --near` also checks near overlaps and reports
only training-row locations, never evaluation text or labels. It uses a bounded
LCS candidate screen when RapidFuzz is installed and verifies every candidate
with difflib; the standard-library fallback is slower but functional.

`stable_split` groups the normalized latest question, including serving's bare
countdown normalization. History and active-set variants cannot straddle the
split. This deliberately changes split membership from the old recipe, so old
synthetic validation scores cannot be compared directly with new scores.

The active-state docs guard is tightened from a tolerated 20× disparity to the
same 2× limit as the history guard. New docs examples include active state both
with and without preceding history, preserving both constraints. The existing
serving workaround remains: data balance alone says nothing about old weights.
The original cardinality distribution guard remains unchanged and passes at
0.031 total-variation distance between active and inactive rows (limit 0.05).
The authored-negative guard still requires over 1,000 boundary rows and now also
permits valid negatives on continuations, topic shifts and documentation turns.

## Validation and remaining work

Compilation and exact/near screening pass against the rebased `develop` catalog;
the committed JSONL and lockfile are generated from the curated YAML. Regression
checks cover holdout histories/context, split grouping and leakage reporting.
Ruff, strict typing, routing coverage, and the shipped routing quality gate pass.
The unchanged selector scores 1,900/2,011 recall-pass, 1,629 strict, and 29/31 docs;
these are validation of the existing artifact, not an improvement from untrained
data. The full repository suite passed before the concurrent PR #156 rebase:
**938 tests, 96.28% coverage**. After rebasing, **313 affected training, catalog,
budget, dependency, loader, example and scenario tests pass**, as do lint, strict
typing and both routing gates. A separate semantic comparison confirms that all
22,495 combined rows match the accepted audit actions and preserved upstream
examples exactly, including provenance and authored negatives.

Retrain stage 1 before stage 2 using the documented recipe. Because this is a
substantial data and split change, compare recipes across seeds and use a fresh,
blind final evaluation suite before claiming generalization. Older development
rounds remain development evidence even after overlapping training rows are
removed. Existing historical context outside the repaired rows can still mention
retired UI or tools; the audit does not certify every old conversation as a
current product transcript.
